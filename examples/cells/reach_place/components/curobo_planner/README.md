# Planner endpoint contract preparation

`manifest.inv` (Panda, seven joints) and `manifest-ur5e.inv` (UR5e, six joints)
describe the approved endpoint contract over the generated C ABI (planner component v2) and
INVP v3 child. Final tool translation uses Euclidean distance <=0.002 m;
orientation uses the sign-invariant quaternion geodesic <=pi/180 rad. Each first
waypoint must agree with every requested start joint within 1e-6 rad. Existing
finite values, joint positions/velocities, increasing timestamps and 2..256-point
capacity remain enforced by the checked boundary.

The harness calls a separately loaded Pinocchio FK component on the **returned
last joint vector**. The planner's reported success or pose is not the oracle.
Both libraries, the exact child, source models, robot/scene configuration,
current FK manifest and its passing record are explicitly selected and hashed.
The planner manifest must declare every selected artifact and the complete FK
source snapshot. FK headers are regenerated from the declared FK manifest and
included in the snapshot without a mutable shared six/seven-joint header file.

The runtime JSON files are deliberately **UNBOUND**: staged artifact files are
absent and their hashes are null. There is no production passing record here.
The legacy v2 requests (four per arm, attached/unattached) predate the planner world phases and are kept as unbound preparation records only.
The source v3 requests (ten per arm) use source-verified Pinocchio joints/tool poses in both directions and every planner world phase (free, approach, held, held_contact, home) with seed 123.
They are generated by `tests/issue_s1_06_planner_requests.rs`
from the goldens and the checked cell: `tool_from_cube` is the inverse of the
cell's declared cube grasp; in free, approach and home the cube rests at its cell pose, and in held and held_contact it starts held at the start tool composed with that grasp.
Home vectors carry the goal golden's joints as their joint goal; the harness requires the last waypoint within 1e-6 rad of it and records `goal_error_rad`.
The child's per-phase world model and held-cube cover are described in `docs/system-integration-v1.md` (Task phases). The
harness refuses requests or runtime scenes that differ from the checked cell.
They have not demonstrated collision-free planning, trajectory feasibility or a
full pick/place sequence. Real planning failures remain failures with retained
observations; do not loosen gates to qualify these requests.

To prepare a separately authorized run in the required pinned Linux environment:

1. Generate each arm's planner and FK headers into distinct new directories with
   `invar component generate MANIFEST --output NEW_DIRECTORY`. Header generation
   does not execute the planner or qualify a manifest. Build the FK through the
   pinned fixture CMake recipe with the corresponding generated include directory.
   Build the planner facade against its arm-specific generated header, for example:

   ```sh
   cc -std=c11 -O2 -Wall -Wextra -Werror -pedantic -fPIC -pthread \
     -I /absolute/new-planner-headers -shared bridge.c planner_reference.c \
     -lm -o /absolute/staged/libinvar_curobo_bridge_v1.so
   ```

2. Derive models and one arm's configuration with the pinned `prepare_models.py
   --arm panda|ur5e` recipe; preserve its exact model/source/FK checks. Pass that
   arm's source v3 runtime with `--runtime`, and its planner-frame table and cube
   poses with `--table-pose-xyzw`, `--table-half-extents` and `--cube-pose-xyzw`;
   the script refuses a table that differs from the runtime.
   For the UR5e it refuses a mount exclusion it cannot honor with a
   configuration-invariant positive table clearance, and with `--scene` (the cell's
   generated MJCF scene) and `--endpoint` it runs `check_ur5e_held_cube_contact.py`
   on the cover it emits; the held cube is ignored against `wrist_2_link` only when
   that record proves the flush flange-face contact joint-invariant and
   non-penetrating.
   For the Panda it maps the pinned cuRobo fit `panda_spheres.json` (decision
   2026-10-14) to URDF link frames on the vendor `franka.yml`; link0's cover clears
   the table, so the Panda runtime must not exclude links. Prove the emitted config
   with `check_panda_spheres.py --spheres panda.yml`: its cover digest must equal the
   one `planner_server.py` pins, or the child refuses the Panda configuration.
   Produce a fresh passing FK contract record from the selected library/model, and
   copy its exact bytes to the staged `fk-evidence.json`. Retain all historical and
   failed records.
3. Stage files at the runtime's declared paths beneath the repository; replace
   every null digest with SHA-256 of the actual bytes. The selected child must
   exactly match this revision's `planner_server.py`. Keep the complete declared
   FK inputs and checked joint order, frames, limits, scene and 50 mm cube. Use
   new run-specific snapshots/output directories for every changed input set.
4. Only after authorization for the exact bounded GPU job, execute:

   ```sh
   timeout 300 /absolute/invar component test manifest-ur5e.inv \
     --library /absolute/staged/libinvar_curobo_bridge_v1.so \
     --model /absolute/staged/ur5e.urdf \
     --child /absolute/repo/examples/cells/reach_place/components/curobo_planner/planner_server.py \
     --planner-runtime runtime-ur5e.json --output /absolute/new-evidence-directory
   ```

   Run in the already pinned environment with bounded memory, no swap and a
   bounded runtime. This document does not authorize a job,
   dependency installation or container pull. The harness bounds JSON/evidence
   to 64 KiB, each runtime file to 64 MiB, and requests to 2..16. Manifest inputs
   retain the stricter existing 16 MiB/file, 64 MiB total and file-count limits.
   The read-only NVIDIA query is bounded to 5 seconds/64 KiB and requires driver
   >=580.65.06; the process adapter retains its configure/plan timeouts. The
   outer timeout bounds trusted in-process FK calls as well.

CPU fixtures use the explicit `cpu-diagnostic` qualification. Their records have
schema `invar-planner-diagnostic-v1` (legacy) or `invar-planner-diagnostic-v2` (cell tool), cannot satisfy passing-record admission,
and cannot be promoted by relabelling schema/status. Production records use
`invar-planner-contract-evidence-v1` (legacy) or `invar-planner-contract-evidence-v2` (cell tool); checking their structure/current digest is
not a signature or build attestation. Selected foreign ABI libraries remain a
trusted native boundary. Failed attempts preserve available entry hashes and
raw endpoint observations in uniquely named records. Evidence publication
never overwrites differing prior bytes.

This component contract covers endpoint/start behavior only. Same-state FK
agreement <=1e-6 m, all trajectory/cube/contact criteria, ROS hashes/builds,
three successful task runs per arm, repeated-seed determinism, planner-kill
failure, finalized MCAP and the <=60 simulated-second gate remain separate
requirements in S1-06. Windows NVRTC map compatibility does not qualify
this planner environment.

The production preparations now use additive runtime/endpoint/evidence **v2**.
`tool_projection` names the pinned reference frame, model/implementation hashes,
anchor body and declared cell tool, with explicit `reference_from_cell` direction.
`cell_source` is a hash-bound manifest input; the harness checks its selected
robot, source scene and computed projection before execution. Historical v1
records remain reference-frame records; v1 rejects a cell projection field.

The adapter derives Panda's hand-to-cell 103.4 mm translation from the declared
cell tool pose, and UR5e's attachment-site-to-cell rotation from the pinned site's
`quat="-1 1 0 0"` and the declared wrist tool pose. No offset is fitted to errors.
FK composes `base_from_reference * reference_from_cell`. Planner goals compose
`base_from_cell * inverse(reference_from_cell)`; attachments compose
`reference_from_cell * cell_from_cube`. Cube/base poses, joints and timing stay
unchanged. Generated cell FK/planner nodes use the same checked helper and emit
`tool-projection.json`. The FK node requires the pinned reference ABI and exact
model bytes; the planner requires its named reference tool. Unknown models or
unsupported anchors fail generation rather than guessing a transform from DOF.
Cell TCP/weld definitions, vendor assets and historical FK goldens stay unchanged.
