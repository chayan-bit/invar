# M4-01 - Versioned floating-point, tensor-shape, and layout semantics

Problem/result: freeze the numerical, shape, and physical-layout contracts that later M4 schedules may consume. The contract must make strict ordered floating point the default, distinguish explicit relaxed/Tensor Core policies, and prevent a layout optimization from changing which bytes or values the source observes.

Dependencies: M3-05.

Contract and implementation: define a versioned `NumericPolicy` covering `f32` operations, explicit fused operations, rounding, subnormals, signed zero, NaN behavior, overflow/error outcomes, and reduction order. Define bounded tensor shapes, rank, zero-length axes, element size, row-major/strided layouts, permutation maps, alignment, and physical-access bounds. Keep logical shape separate from allocation identity and require a checked mapping from every logical index to bytes. Preserve the typed interaction extraction path: a region is eligible only after its typed ports, affine permissions, demand/effects, and physical accesses are verified. Add the policy, shape, layout, and version to MIR/device IR, admission records, and cache keys. Freeze the APIs, concrete grammar and semantic fixtures first, then implement the minimal public f32/shape surface in this issue across parser, checker, independent source interpreter and native backend. Initial IR-only tests are a development step and cannot complete acceptance. Extend the built-in array element set with f32 and recognize rank-2 contraction shapes from ordinary counted loops and checked flattened indices; no general user generics or escaping strided views are needed. Internal rank/stride descriptors are not public borrowed views (L1-02 owns those). Use the existing M3 `cuda` feature name and keep the first device target NVIDIA.

Positive cases: exact CPU/reference agreement for `+`, `*`, explicit `fma`, `+0/-0`, subnormal boundaries, NaNs, cancellation, and zero/one/odd tensor axes; valid contiguous, transposed, and bounded-stride views; stable serialization and cache invalidation when any policy, shape, layout, or version changes. Negative cases: implicit reassociation or FMA under strict policy, silent fast math, unknown strides, negative/out-of-range dimensions, byte-size overflow, misaligned or widened physical access, stale policy/cache versions, aliasing that violates a view, and unsupported device capability. Each rejection must retain the CPU/reference fallback or a typed admission error.

Acceptance interface and evidence: add `issue_m4_01_numeric_layout_contracts`; first require `cargo test --locked -- --list | rg -q 'issue_m4_01_numeric_layout_contracts'` (a missing match fails), then run `cargo test --locked issue_m4_01_numeric_layout_contracts`. Record policy/version fixtures, bit-level outcomes, shape/layout mappings, verifier diagnostics, mutation results, and whether checks ran on CPU, a mock, or a real device. Before future hardware qualification, require `cargo test --locked --features cuda -- --list | rg -q 'issue_m4_01_gpu'`; then use `cargo test --locked --features cuda issue_m4_01_gpu -- --ignored --nocapture`. A mock or missing GPU is not a pass, and no GPU run is part of this draft.

Exclusions/stop: no Tensor Core schedule, layout optimizer, fast-math default, unrelated public syntax, multiple GPU vendors, or performance claim. Stop when the minimal source extension runs through reference/native execution and its versioned contracts are consumed by typed interaction extraction and device verification. Ordinary high-level matrix fixtures must parse and execute; constructing IR by hand is not sufficient.

Shared acceptance: follow `docs/implementation-plan.md`, require a nonzero relevant test selection and run Debug/Release. Explicit GPU qualification must fail on missing hardware; ignored-only or mock-only success does not complete a hardware gate. Source-invalid programs remain errors in every engine; only optimization-specific unknown legality selects a lawful fallback.

## Independent baseline (from M5-01)

CUDA: CUB `DeviceTransform` (Thrust `transform` only where the pinned CUB lacks it) for f32 fused maps, and CUB `DeviceReduce` and `DeviceScan` for `reassoc_add` reductions and scans. Metal: MPS reduce or scan equivalents where they exist; otherwise, and for f32 fused maps, a reviewed handwritten Metal kernel pinned by content hash. M5-01 follows this issue directly, so the f32 gates are first measured when M5-01 lands. Its gate is measured through the M5-01 harness against the frozen `bench/manifest-v1.json` entry for this family and against the M5-01 held-out program set, on the RTX 5070 Ti (sm_120) and the Apple M4 (local Metal); the agent-written same-structure fixture is secondary and never sets the gate.

Amended 2026-10-14: the CUDA performance gates in this contract are measured on an NVIDIA RTX 5070 Ti (sm_120, driver 580.178.04) and, for Metal, on the Apple M4, replacing the earlier RTX A6000 target. No threshold value changes. Every fraction of peak is taken against a reference measured on that same GPU (device-to-device copy bandwidth, or the measured compute peak where this contract defines one), never a datasheet number.
