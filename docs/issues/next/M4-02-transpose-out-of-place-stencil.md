# M4-02 - Transpose and out-of-place stencil scheduling

Problem/result: extract two useful multidimensional operations from ordinary high-level loops: rectangular transpose and an out-of-place radius-1 stencil. Generate schedules that preserve the M4-01 shape/layout and numeric contracts while retaining a correct CPU path.

Dependencies: M4-01, M5-01.

Contract and implementation: add typed `Transpose` and `Stencil2D` region forms only after the source region has passed the required interaction encoding, demand/effect checks, and extraction relation. Transpose must specify logical index mapping, source/destination layouts, empty axes, bounds, and nonoverlapping output writes. The initial stencil is out-of-place, with the frozen versioned boundary policies `constant_zero` and `clamp`; each step reads one completed time slice and writes a fresh slice. Multi-step execution uses explicit ping-pong buffers and separate device phases, never an in-place cross-block update. Lower to bounded device IR with padded shared-memory tiles, masked edge loads/stores, uniform barriers, and checked byte/index arithmetic. Preserve strict ordered floating behavior from M4-01; a relaxed policy must be explicit in the region contract. Unknown strides, aliases, halos, or barrier participation select serial fallback.

Positive cases: transpose shapes `0xN`, `1x1`, `31x33`, `127x257`, and bounded square cases; round-trip transpose with independently derived indexing; radius-1 stencils on tiny, odd-width, wide, and tall domains under each frozen boundary policy; one and several ping-pong steps; CPU/reference and extracted serial equality. Negative cases: in-place aliasing, nonmonotone or unknown strides, out-of-bounds halo reads, skipped barrier lanes, widened/padded overreads, wrong time-slice reads, strict-versus-relaxed numeric mismatch, and allocation/completion failure. The candidate must reject or fall back without publishing partial output.

Acceptance interface and evidence: add `issue_m4_02_transpose_stencil_schedules`; first require `cargo test --locked -- --list | rg -q 'issue_m4_02_transpose_stencil_schedules'` (a missing match fails), then run `cargo test --locked issue_m4_02_transpose_stencil_schedules`. Cover the performance protocol's `Transpose/layout` and `Stencil` families. Archive logical-to-physical access maps, boundary/halo policy, generated IR/source hashes, tile geometry, barrier checks, fallback reason, and CPU/reference outputs. When authorized hardware exists, first require `cargo test --locked --features cuda -- --list | rg -q 'issue_m4_02_gpu'`, then run `cargo test --locked --features cuda issue_m4_02_gpu -- --ignored --nocapture` and report device, driver, transfers, completion, and timing boundaries separately. No GPU run is performed for this drafting task; mocks and no-device verifier results remain incomplete qualification.

Exclusions/stop: no matrix contraction, segmented flattening, arbitrary in-place stencils, global barriers, autotuning, or claim of CUDA-class performance. Stop when one transpose and one out-of-place stencil are bounded, interaction-extracted, physically verified, and fallback-safe.

Shared acceptance: follow `docs/implementation-plan.md`, require a nonzero relevant test selection and run Debug/Release. Explicit GPU qualification must fail on missing hardware; ignored-only or mock-only success does not complete a hardware gate. Source-invalid programs remain errors in every engine; only optimization-specific unknown legality selects a lawful fallback.

## Independent baseline (from M5-01)

CUDA: the NVIDIA reference tiled shared-memory transpose for transpose, and a reviewed handwritten tiled stencil pinned by content hash (no library primitive exists). Metal: a reviewed handwritten Metal transpose and stencil pinned by content hash, unless an MPS primitive with the same contract exists at the pinned macOS version. Its gate is measured through the M5-01 harness against the frozen `bench/manifest-v1.json` entry for this family and against the M5-01 held-out program set, on the RTX 5070 Ti (sm_120) and the Apple M4 (local Metal); the agent-written same-structure fixture is secondary and never sets the gate.

Amended 2026-10-14: the CUDA performance gates in this contract are measured on an NVIDIA RTX 5070 Ti (sm_120, driver 580.178.04) and, for Metal, on the Apple M4, replacing the earlier RTX A6000 target. No threshold value changes. Every fraction of peak is taken against a reference measured on that same GPU (device-to-device copy bandwidth, or the measured compute peak where this contract defines one), never a datasheet number.
