# M4-05 - Gather/scatter conflict semantics and bounded frontier work

Problem/result: support useful irregular indexed work while rejecting races and unbounded work discovery. Add safe gather, injective scatter, named conflict reductions, and bounded level-synchronous frontier rounds through the typed interaction extraction path.

Dependencies: M4-04.

Contract and implementation: a gather validates every index and read footprint. A scatter is admitted only when writes are proved injective, or when the compiler derives a named associative/commutative identity law from source operations, such as wrapping_add in a modular histogram update with a defined duplicate policy. User-supplied proof flags are not trusted. Atomics are an implementation of that contract, never a legality proof. Frontier work uses explicit rounds, owned worklists, stable compaction, capacity limits, and separate launches/events between phases. It may expose a set or per-level result only when source observations permit that order; an order-sensitive source remains sequential. Physical aliasing, bounds, ownership, demand, and completion remain checked after flattening. Pointer chasing and unknown successor counts must retain a bounded CPU fallback or a typed limit outcome.

Positive cases: sorted and random in-bounds gathers; injective scatters; duplicate indices under the named modular histogram law; empty, singleton, chain, star, balanced, skewed, and ragged frontiers with bounded rounds; serial/reference and extracted outputs agree. Negative cases: duplicate noncommutative writes, out-of-bounds or negative indices, unknown aliasing, unstable order where observable, unbounded frontier growth, queue overflow, missing phase completion, failed guard, and partial device mutation. Each negative case must reject or fall back without silently selecting atomics or weakening source observations.

Acceptance interface and evidence: add `issue_m4_05_gather_scatter_frontier`; first require `cargo test --locked -- --list | rg -q 'issue_m4_05_gather_scatter_frontier'` (a missing match fails), then run `cargo test --locked issue_m4_05_gather_scatter_frontier`. Cover the performance protocol's `Gather/scatter` and `Irregular frontier` families. Record index proofs, conflict-law IDs, frontier capacities/rounds, compaction maps, physical accesses, interaction extraction evidence, failure prefixes, and fallback reasons. Authorized NVIDIA qualification first requires `cargo test --locked --features cuda -- --list | rg -q 'issue_m4_05_gpu'`, then uses `cargo test --locked --features cuda issue_m4_05_gpu -- --ignored --nocapture`, with the device, driver, transfer, and completion record required; no GPU run is part of this draft and mock results are not qualification.

Exclusions/stop: no arbitrary graph algorithms, lock-free global task queues, multi-device work stealing, source-order weakening, or universal irregular parallelism claim. Stop when bounded frontier and conflict modes are fail-closed and independently checked against the performance families.

Shared acceptance: follow `docs/implementation-plan.md`, require a nonzero relevant test selection and run Debug/Release. Explicit GPU qualification must fail on missing hardware; ignored-only or mock-only success does not complete a hardware gate. Source-invalid programs remain errors in every engine; only optimization-specific unknown legality selects a lawful fallback.

## Independent baseline (from M5-01)

CUDA: Thrust `gather` and `scatter` (CUB lacks these primitives), CUB `DeviceHistogram` for the modular histogram, and a reviewed handwritten level-synchronous frontier kernel pinned by content hash. Metal: a reviewed handwritten Metal kernel pinned by content hash for each family. Its gate is measured through the M5-01 harness against the frozen `bench/manifest-v1.json` entry for this family and against the M5-01 held-out program set, on the RTX 5070 Ti (sm_120) and the Apple M4 (local Metal); the agent-written same-structure fixture is secondary and never sets the gate.

Amended 2026-10-14: the CUDA performance gates in this contract are measured on an NVIDIA RTX 5070 Ti (sm_120, driver 580.178.04) and, for Metal, on the Apple M4, replacing the earlier RTX A6000 target. No threshold value changes. Every fraction of peak is taken against a reference measured on that same GPU (device-to-device copy bandwidth, or the measured compute peak where this contract defines one), never a datasheet number.
